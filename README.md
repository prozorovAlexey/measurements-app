# measurements-app

Статическое PWA для хранения и просмотра замеров тела. Приложение развёрнуто на
GitHub Pages, а приватные данные читает и записывает через GitHub Contents API.

### Результаты

1. **ЧАСТИЧНО — сайт открывается с телефона и с ПК.** GitHub Pages вернул `200`
   для desktop- и mobile-User-Agent по адресу
   `https://prozorovalexey.github.io/measurements-app/`. Отрисовка не проверена:
   интерактивный браузерный стенд был недоступен. Нужен ручной запуск на реальном
   ПК и телефоне с проверкой четырёх вкладок.

2. **ЧАСТИЧНО — шпаргалка работает в авиарежиме.** В коде подтверждены кэш
   оболочки в `sw.js` и первая отрисовка шпаргалки из `bm.index_cache` до сетевого
   запроса в `screens/cheatsheet.js`. Реальный холодный старт в авиарежиме не
   выполнялся. Нужен ручной прогон: один раз открыть приложение онлайн, дождаться
   данных, включить авиарежим, закрыть и снова открыть PWA; значения и пометка о
   кэше должны остаться на экране.

3. **ЧАСТИЧНО — офлайн-сессия доезжает после появления сети.** `screens/entry.js`
   сначала кладёт каждую сессию в IndexedDB-очередь, затем вызывает отправку;
   `app.js` повторяет отправку при старте и по событию `online`. Сквозной прогон с
   реальным GitHub и переключением сети не выполнялся. Нужен ручной прогон с PAT:
   сохранить сессию в авиарежиме, включить сеть и убедиться, что задание исчезло
   из очереди и появился новый файл в repo B.

4. **ЧАСТИЧНО — ввод с двух устройств в один день не теряет данные.** В начале
   прогона `queue.js` один раз получает листинг каталога, выбирает по нему свободное
   имя (`--2`, `--3`, …), а после успешной записи обновляет локальную копию листинга.
   Файл создаётся без `sha`, конфликт остаётся в очереди для повтора. Одновременная
   отправка с двух физических устройств не выполнялась. Нужен ручной прогон:
   поставить разные сессии одной датой в офлайн-очередь на двух устройствах, почти
   одновременно включить на них сеть, затем проверить два отдельных файла и две
   записи в `index.json`.

5. **PASS — в `index.html` нет внешних ссылок на скрипт или шрифт.** Поиск
   `https?://|@import|fonts\.` не нашёл совпадений (`rg` завершился с кодом `1`).
   Единственные подключения именно стиля и скрипта локальные:

   ```text
   ./style.css
   ./app.js
   ```

   Кроме них, `index.html` содержит локальные ссылки на `manifest.json` и иконку;
   они не являются подключениями стиля или скрипта.

6. **ЧАСТИЧНО — repo B недоступен без токена.** Неавторизованные запросы вернули
   `404` как для GitHub Repository API, так и для raw `index.json`:

   ```text
   REPO_API_UNAUTH status=404
   RAW_INDEX_UNAUTH status=404
   ```

   Это подтверждает отсутствие публичного доступа без передачи credentials, но
   приватное окно буквально не использовалось. Нужен ручной прогон: открыть в
   приватном окне без авторизации страницу repo B и raw `index.json` и убедиться,
   что ни список файлов, ни содержимое данных не доступны.

7. **ЧАСТИЧНО — отозванный токен даёт понятную ошибку вместо белого экрана.**
   Запрос с заведомо недействительным токеном вернул `401`. `github.js` переводит
   его в сообщение «Токен недействителен или отозван. Нужен новый PAT.», а экран
   шпаргалки рисует ошибку карточкой. Настоящий PAT не отзывался, и итоговая
   отрисовка в браузере не проверялась. Нужен ручной прогон с отзывом тестового PAT.

8. **НЕ ПРОВЕРЕНО — экспорт JSON содержит все внесённые сессии.** В локальной
   копии repo B нет файлов `data/*.json`, а PAT для чтения удалённых сессий не
   предоставлен. Код экспорта перечисляет `data/`, читает каждый файл, добавляет
   корректные сессии из офлайн-очереди и скачивает JSON-массив, но это не заменяет
   проверку данных. Нужен ручной экспорт с последующим сравнением количества и
   содержимого сессий с repo B и очередью.

9. **PASS — правки старой сессии невозможны через UI.** В production/runtime-коде
   единственный импорт `writeFile` находится в `queue.js`; экраны его не импортируют.
   Единственный runtime-вызов создаёт новый файл без `sha`:

   ```text
   writeFile(path, job.content, { message: job.message })
   ```

   Поиск вызова `writeFile` с `sha` по `*.js` с исключением `*.selftest.js` и
   `*.selftest.mjs` совпадений не нашёл. Следовательно, production UI не имеет пути
   к GitHub Contents API для перезаписи существующего файла сессии.
